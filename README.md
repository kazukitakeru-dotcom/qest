# QUEST LIST

やることをクエストとして管理するPWA。
公開先は https://kazukitakeru-dotcom.github.io/qest/

## 構成

| ファイル | 中身 |
|---|---|
| `index.html` / `style.css` | 画面 |
| `app.js` | 全ロジック（DB・描画・自動追加・バックアップ） |
| `sync.js` | 複数端末同期（Supabase） |
| `sw.js` / `manifest.json` / `icons/` | PWA |
| `supabase.sql` | Supabase のテーブル定義。ダッシュボードの SQL Editor に貼って実行する |

## データ

IndexedDB `questlist`（**v2**）。すべて `keyPath: 'id'`。

- `quests` … 手持ちのクエスト
- `templates` … テンプレート（`recurring: true` なら毎朝の自動追加対象）
- `recurring` … 旧仕様の繰り返し定義
- `history` … 完了したクエスト（`completedAt` 付き・追記のみ）

同期のための内部ストア（バックアップの書き出し・復元の対象外）：

- `tombstones` … 消したものの墓標。`{ id: 'store:itemId', store, itemId, at }`
- `meta` … 端末間で共有する小さな値。今は `{ id:'app', lastRecurring: 'YYYY-MM-DD' }` だけ

## 改修時の注意

- **ファイルを更新したら `sw.js` の `CACHE_NAME` を必ず上げる。**
  上げないと古いキャッシュが配られて変更が届かない。新しいファイルは `FILES_TO_CACHE` にも足す。
  ローカル検証中も `getRegistrations().unregister()` ＋ `caches.delete()` してからリロードしないと
  古いコードを掴む。
- **消すときは `dbDelete` / `dbClear` を通す。** この2つが墓標を自動で残す。
  `dbRawDelete` は同期の内部処理用で、墓標を残さない。
- **`todayStr()` は UTC 基準**。日本時間の 0〜9時は前日を返す。
  履歴の集計は `completedAt`（UTCのISO文字列）と突き合わせているのでこれでよいが、
  日付そのものを扱うときは `todayLocalStr()`（暦の今日）を使う。
  自動追加が「4時なのに朝9時まで走らない」のはこれが原因だった。

## 毎朝4時の自動追加（複数端末での落とし穴）

以前の作りは端末ごとに壊れていた。

- 「最後に走らせた日」を `localStorage.questLastRecurring` に持っていた → **端末ごとに走る**
- 走るたびに「`recurringDefId` が付いたクエスト全部」を消して**ランダムIDで作り直す**

この2つが重なると、スマホで4時に追加されたクエストをPCが消し、別IDで作り直し、
同期で二重に増え、スマホで消したはずのものが復活する。

今の作りは：

- 「最後に走らせた日」は `meta.lastRecurring`（同期対象）。取り込み時は**後の日付が勝つ**
  （last-write-wins にすると、古い日付を持つ端末が後から書いて自動追加がもう一度走る）
- 生成するIDは **`rec:{テンプレID}:{YYYY-MM-DD}` の決め打ち**。両端末が同じIDを作るので二重にならない
- 片付けるのは **`recurringDate` が今日ではないものだけ**。全部消すと、もう一方の端末が
  今日ぶんとして作ったばかりのクエストまで巻き込む
- 作る前に「手持ちにある / 履歴にある / 墓標がある」を確認する。
  他の端末で今日ぶんを完了・削除済みなら作り直さない

## 複数端末同期の設計

同じ Supabase プロジェクトに、わんにゃんメモリー／達人への道／IRON LOG／URUOI と相乗り。
ログインはメール＋パスワード。未ログインなら同期処理は一切走らず、導入前と同じ挙動になる。

4ストアとも「IDを持つレコードの集合」で同じ形なので、`qest_items` 1テーブルに
`store` 列で区別して入れている。行単位の last-write-wins ＋ 墓標。

- 取り込むか送るかの判定は**ハッシュ比較**。手元の姿がサーバーと合意済みのハッシュと違えば
  「未送信のローカル変更あり」と見て、取り込みをスキップして送信側に回す
- ハッシュは**キーを並べ替えてから**取る。Postgres の jsonb はキー順を保たないので、
  素の `JSON.stringify` で比べると中身が同じでも「変わった」と誤判定して送り直しが続く
- `updated_at` は**サーバーの `now()`**（トリガ）。端末の時計で入れると、時計がずれた端末の行が
  差分同期の網から永久に漏れる
- 取得位置は 5 秒だけ巻き戻して覚える（commit の順と `now()` のズレ対策）
- 1回の GET は 1000 件が上限なので `_restAll()` でページを送る。履歴は増え続けるので必須
- 取り込み後に「履歴にあるものは手持ちのクエストではない」を必ず成り立たせる（`_reconcile`）。
  片方で完了したクエストが、まだ持っている側から押し戻されるのを防ぐ
- クラウドの内容を反映する直前にこの端末のデータを丸ごと控える。設定 → 同期 の
  「取り込み前に戻す」で1タップ戻せる

### テーブルを足すとき

複数アプリの相乗り前提なので、毎回
**「`authenticated` に grant ／ `anon` から revoke ／ RLS＋ポリシー」を明示する**こと。
実例は `supabase.sql`。
